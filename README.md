## Обзор

Проект реализует контур управления дроном Tello, в котором оператор выступает в роли "маяка": дрон удерживает человека в центре кадра, реагирует на его смещение изменением положения в пространстве, а отдельные жесты (поднятые руки, опущенные руки, наклон корпуса) используются как команды взлёта, посадки и бокового смещения.

Обработка видеопотока выполняется на двух моделях параллельно:

- **yolov8n-pose** — детекция ключевых точек скелета (COCO, 17 точек).
- **best.pt** — кастомный классификатор жестов, обученный под конкретную задачу.

## Возможности

- Автоматический взлёт по жесту `go_up`.
- Автоматическая посадка по жесту `go_down`.
- Удержание оператора в центре кадра по осям X и Y.
- Регулировка дистанции (вперёд/назад) по площади проекции корпуса.
- Боковое смещение по жестам `go_left` / `go_right`.
- Выбор целевого человека: приоритет отдаётся наиболее крупной фигуре вблизи центра кадра.
- Мёртвые зоны по осям для устранения дрожания управления.
- Визуализация скелета, центра тела, площади, текущей команды и жеста.
- Безопасное завершение: остановка RC-каналов, выключение стрима, отключение дрона.

## Конфигурация

Все ключевые параметры вынесены в начало `main.py`.

| Параметр | Значение | Назначение |
|---|---|---|
| `DEAD_ZONE_X` | 150 px | Мёртвая зона по горизонтали |
| `DEAD_ZONE_Y` | 100 px | Мёртвая зона по вертикали |
| `GESTURE_CONF_THRESH` | 0.7 | Минимальная уверенность распознавания жеста |
| `GESTURE_CLASSES` | `["neutral", "go_up", "go_down", "go_left", "go_right"]` | Порядок классов в модели |
| `POSE_MODEL` | `yolov8n-pose.pt` | Модель детекции позы |
| `GESTURE_MODEL` | `best.pt` | Модель классификации жестов |

### Пороговые значения в `get_command`

| Условие | Действие |
|---|---|
| `area > 30000` | Движение назад |
| `area < 7000` | Движение вперёд |
| `body_x` вне мёртвой зоны | Поворот влево/вправо |
| `body_y` вне мёртвой зоны | Вверх/вниз |

## Запуск

1. Подключитесь к Wi-Fi сети дрона Tello.
2. Убедитесь, что модели `yolov8n-pose.pt` и `best.pt` доступны.
3. Запустите:

```bash
python main.py
```

4. Дождитесь сообщения `Ожидание жеста для взлёта`.
5. Покажите жест `go_up` — дрон взлетит и перейдёт в режим трекинга.
6. Для посадки покажите жест `go_down`.
7. Для аварийного завершения нажмите `q` в окне или `Ctrl+C` в терминале.

## Логика работы

### Инициализация

Функция `drone_init` выполняет подключение, выводит уровень заряда батареи, настраивает FPS и битрейт видеопотока, принудительно перезапускает стрим и обнуляет RC-каналы.

### Ожидание взлёта

`wait_for_takeoff` в цикле считывает кадры, классифицирует жест и ждёт появления `go_up`. Параллельно в окне отображается текущий статус и распознанный жест. Выход — по клавише `q` или по достижении целевого жеста.

### Основной цикл

`process_frame` выполняет полный конвейер обработки кадра:

1. Ресайз до 640x480.
2. Инференс модели позы, извлечение ключевых точек.
3. Выбор целевого человека через `select_target_person`.
4. Классификация жеста через `check_gesture`.
5. Обработка боковых жестов через `get_right_left`.
6. Формирование команды через `get_command`.
7. Наложение аннотаций через `annotate_frame`.

### Завершение

Блок `finally` гарантирует остановку RC-каналов, отключение стрима, освобождение ресурсов дрона и закрытие окон OpenCV независимо от причины выхода.

## Управляющие жесты

| Жест | Класс | Действие |
|---|---|---|
| Нейтральное положение | `neutral` | Удержание позиции |
| Поднятые руки | `go_up` | Взлёт |
| Опущенные руки | `go_down` | Посадка |
| Наклон влево | `go_left` | Смещение влево (RC: `30` по X) |
| Наклон вправо | `go_right` | Смещение вправо (RC: `-30` по X) |

## Алгоритм трекинга

### Выбор целевого человека

`select_target_person` перебирает всех обнаруженных людей и применяет фильтры:

- Минимум 13 ключевых точек (отсечение неполных скелетов).
- Площадь корпуса не менее 5000 px².
- Горизонтальное отклонение от центра кадра не более 40% ширины.
- Приоритет — наибольшая площадь с гистерезисом 1.2 (защита от частого переключения между людьми).

### Центр тела

`calculate_body_center` усредняет координаты четырёх точек: левое и правое плечо, левый и правый бедро. Это устойчивая метрика центра масс верхней части тела.

### Площадь корпуса

`calculate_body_area` вычисляет площадь четырёхугольника по формуле шнуровки (shoelace formula) через те же четыре ключевые точки. Метрика используется как прокси дистанции до оператора.

### Генерация команд

`get_command` реализует приоритетное дерево решений:

1. Отклонение по X → поворот.
2. Отклонение по Y → вертикальное смещение.
3. Площадь корпуса → движение вперёд/назад.
4. Иначе → полная остановка.

Приоритет отдан горизонтали и вертикали, так как стабилизация положения в кадре критичнее регулировки дистанции.

## Известные ограничения

- Жёсткая привязка индексов классов жестов к порядку в `GESTURE_CLASSES` — при переобучении модели порядок необходимо синхронизировать.
- Использование `time.sleep` в блокирующих участках (взлёт, посадка) задерживает обработку видеопотока.
- Отсутствие стабилизации по рысканию (yaw) на основе позы — поворот выполняется только по смещению центра тела.
- Пороговые значения площади корпуса (7000 и 30000) подобраны эмпирически и зависят от разрешения кадра и дистанции.
- Двойной инференс YOLO на каждом кадре создаёт заметную нагрузку; при слабом GPU возможна просадка FPS.

## Диагностика

| Симптом | Вероятная причина | Решение |
|---|---|---|
| `Ожидание первого кадра` не завершается | Стрим не запущен или Wi-Fi не подключён | Перезапустить дрон, проверить сеть |
| Жесты не распознаются | Модель `best.pt` не загружена или порядок классов не совпадает | Проверить `GESTURE_CLASSES` и файл модели |
| Дрон дёргается в нейтральном положении | Слишком узкие мёртвые зоны | Увеличить `DEAD_ZONE_X`, `DEAD_ZONE_Y` |
| Дрон не удерживает дистанцию | Пороги площади не соответствуют сцене | Откалибровать значения в `get_command` |
| Посадка не срабатывает | Низкая уверенность жеста `go_down` | Снизить `GESTURE_CONF_THRESH` или переобучить модель |
| Низкий FPS | Двойной инференс на CPU | Использовать GPU или меньшую модель позы |
